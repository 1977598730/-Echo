# 中文文档排版

## 何时使用

- 写或改 `docs/**`、`README.md`、需求/设计/迁移文档
- 给代码补中文注释、写 PR 描述与交付说明

## 排版规则

| 场景          | 规则                                                 | 正例                                                 | 反例                              |
| ------------- | ---------------------------------------------------- | ---------------------------------------------------- | --------------------------------- |
| 中英文相邻    | 之间加一个半角空格                                   | 使用 Vue 3 的 Composition API                        | 使用Vue3的CompositionAPI          |
| 中文与数字    | 之间加空格                                           | 面板宽 306 px，共 12 项                              | 面板宽306px，共12项               |
| 标点          | 中文语境用全角，纯英文/代码语境用半角                | 已完成（含验证）。                                   | 已完成(含验证).                   |
| 括号          | 括号内是中文 → 全角；是缩写/代码 → 半角              | 大屏（1920 × 1080 基准）                             | 大屏(1920 × 1080 基准)            |
| 引号          | 统一用 `「」` 或 `“”`，一份文档内不混用              | 「林情分析」区块                                     | "林情分析"区块                    |
| 术语          | 保留官方英文原名与大小写                             | Vue 3、Pinia、Element Plus、Cesium、Vite、TypeScript | vue3、element-plus、CesiumJS 引擎 |
| 破折号/省略号 | 用中文全角 `——` `……`                                 | 原因——依赖未装                                       | 原因--依赖未装                    |
| 常见错别字    | 登录（非"登陆"）、账号（非"帐号"）、组件（非"组建"） | 重新登录                                             | 重新登陆                          |

## 代码与链接

- 行内代码、文件名、类名、CSS 属性一律用反引号：`.el-tabs__item`、`useTemplateRef`
- 引用项目文件给相对路径，必要时带行号：`src/hooks/useEchart.ts:9`
- 外部链接写成 `[显示文字](https://...)`，不贴裸 URL
- 代码块标注语言：` ```ts `、` ```scss `、` ```bash `
- 图片：需要构建处理的放 `src/assets/**`，文档配图放 `docs/images/**`，文档内用相对路径引用

## 注释规范

- 注释解释**为什么**，不复述代码在做什么；中文一行摘要用 `/** ... */`
- 导出的函数、类型、组件都要有一行中文摘要
- SCSS 大区块用分隔注释（见 `.qoder/rules/project-structure.md`）：

```scss
/* ========== 页签栏 ========== */
```

- 从设计稿推导出的数值，注释里写来源与算式，便于后续复核：

```scss
/* 设计稿：体框 278x180，列表容器 262x161 → 上 9 / 左右 7 / 下 8 */
padding: 9px 7px 8px;
```

## 文档归属

| 类型               | 位置                                                               |
| ------------------ | ------------------------------------------------------------------ |
| 架构 / 框架说明    | `docs/pdr/`                                                        |
| 实施计划           | `docs/superpowers/plans/<日期>-<主题>.md`                          |
| 设计方案           | `docs/superpowers/specs/<日期>-<主题>-design.md`                   |
| 迁移手册、缺陷报告 | `docs/` 根目录，文件名见义                                         |
| 工程说明           | `README.md`                                                        |
| 知识库             | `.qoder/repowiki/`（用 `repowiki` skill 查阅，不要整本复制进规则） |

## 交付文档结构模板

```markdown
# <主题>

## 背景

## 现状（附证据：命令 + 输出摘要）

## 方案

## 影响面

## 验证

## 遗留与待办
```

要点：**结论必须有证据**。写"已通过验证"就要附上跑了什么命令、结果是什么；没做的验证要显式写"未验证"，不要用模糊表述掩盖。

## 反例

- 中英文不加空格，整段挤成一坨
- 文档里把接口字段翻译成中文，与代码实际字段名不一致（应以代码/接口文档为准）
- 只写"已优化样式"，不写改了哪些数值、依据哪张设计稿
- 把长文档塞进 `.qoder/rules/`（规则要短、要可执行，长内容进 `docs/` 或 repowiki）
